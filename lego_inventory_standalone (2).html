Update on-hand counts from your full inventory

Already have a spreadsheet of everything you own (e.g. a Rebrickable or BrickLink export)? Upload it here to set the on-hand quantity for every matching part across all your builds in one go — this overwrites the on-hand numbers currently in the app for any part it matches.

Needs a Part Num column and a Quantity column (however labeled — Qty, Owned, Amount, Stock, etc. are all recognized). A Color column is optional but recommended: if present, matching is by part number + color; if absent, matching is by part number alone across all colors of that part.

Recommended: host images with your site

The most reliable option isn't caching in the browser at all — it's downloading the images once and putting them in your GitHub repo as real files, right next to index.html. Then they load instantly from your own site for every visitor, with no CORS proxy, no per-browser storage limit, and no dependence on lego.com staying reachable.

  1. Download the script below and run python3 download_part_images.py on your own computer (needs internet; no extra installs required).
  2. It creates an images folder containing one .jpg per part.
  3. Copy that images folder into your GitHub repo, at the same level as index.html, and push.

The app already checks images/<element id>.jpg on your site first, before ever trying a cache or lego.com — so this works automatically as soon as the folder exists. Re-run the script any time you add new parts; it skips files it already has.

Fallback: cache in this browser instead

Once an image is cached here, it's stored in the app itself and will keep showing even with no internet connection.

LEGO's own site blocks the direct download this feature needs (a browser security rule called CORS), so plain automatic caching usually fails silently. Turning this on routes image requests through images.weserv.nl, a free public image proxy, which re-serves the image with permission attached so caching can work. This means that third-party service sees which LEGO part images you're requesting. Off by default; the manual upload below never uses any third party.

Needs internet the first time. Without the proxy above, most browsers will block this automatic download for cross-site images — if a part stays uncached after trying, use the manual upload below instead. Cached images are stored in this browser's local storage, which typically holds 5–10MB total — plenty for a few hundred thumbnails, but caching every part across all builds may eventually hit that limit.

Or add images yourself: select image files whose filenames are the element ID (e.g. 6269079.jpg). No internet needed for this step.
